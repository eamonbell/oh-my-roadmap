# /milestone:plan

Plan the next active roadmap milestone. Compare the selected approved roadmap milestone outline with decisions, risks, prior notes, amendments, closeout evidence, relevant existing code, and relevant documentation. Use `roadmap_engineer_search_context` first for decisions, risks, and prior notes, then `roadmap_engineer_read_context` for selected entries that need full detail. Expand that outline into a milestone plan; do not invent scope outside the approved roadmap. Use the built-in `ask` tool to interview the user until no implementation decisions, acceptance gaps, ownership gaps, verification gaps, cleanup questions, test coverage decisions, or approval questions remain. Explicitly ask what test coverage the user wants based on the required implementation: which areas/tasks should create tests, which should only run existing tests, what detail those tests should cover, and what is intentionally untested or deferred. Define concrete executable tasks before dependency analysis or wave creation; every task needs objective, implementation notes, done criteria, task verification commands, dependencies, exclusive ownership, shared interfaces, and worker assignment. Convert the test coverage decisions into task-level done criteria and verification commands. Perform dependency analysis over that task list, then group those task IDs into waves with goals, exit criteria, and review checkpoints. Include the persisted progress cursor initialized to the first wave with step `not_started`. Use `roadmap_engineer_transition` with `create_milestone_plan`, then validate before approval.
