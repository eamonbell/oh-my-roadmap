# /roadmap:new

Create a new gated roadmap workflow. Inspect existing code and documentation before drafting. Use the built-in `ask` tool to interview the user until goal, success criteria, audience, constraints, scope, discovery findings, external research needs, open questions, milestone intent, and approval state are clear. Include relevant existing code and documentation paths in the roadmap where useful. Use `roadmap_engineer_init` once the roadmap slug and title are known, then use `roadmap_engineer_transition` with `record_discovery` when repo discovery is complete.
