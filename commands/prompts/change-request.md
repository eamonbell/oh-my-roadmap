# /change:request

Create a post-implementation change request. Use the original milestone plan, actual notes, changed work, evidence bundle, user request, relevant existing code, and relevant documentation as context. Use `roadmap_engineer_search_context` first for actual notes, decisions, risks, and issues, then `roadmap_engineer_read_context` for selected entries that need full detail. Use the built-in `ask` tool to interview the user until the requested delta, acceptance criteria, verification, ownership, risk, and approval questions are closed. Produce a decision-complete change plan with the same wave, ownership, review, evidence model, and code/docs references where useful. Use `roadmap_engineer_create_change_request`.
