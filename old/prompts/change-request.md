# /change:request

Create a post-implementation change request. Use the original milestone plan, actual notes, changed work, evidence bundle, user request, relevant existing code, and relevant documentation as context. Use `roadmap_engineer_search_context` first for actual notes, decisions, risks, and issues, then `roadmap_engineer_read_context` for selected entries that need full detail. Use the built-in `ask` tool to interview the user until the requested delta, acceptance criteria, verification, ownership, risk, and approval questions are closed. Produce a decision-complete change plan with the same wave, ownership, review, evidence model, and code/docs references where useful. Assign each task to `worker-light`, `worker`, or `worker-heavy` using the same risk/blast-radius rubric as milestone planning. Use `roadmap_engineer_create_change_request`, dispatch `wave-flow-checker`, record the result with `record_wave_flow_check`, revise with `update_change_request_plan` if it fails, and only ask for approval after the checker passes.
