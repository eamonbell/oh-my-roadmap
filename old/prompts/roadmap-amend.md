# /roadmap:amend

Record an approved roadmap amendment. Inspect the current roadmap, decisions, risks, relevant code, and relevant documentation before proposing the amendment. Use `roadmap_engineer_search_context` first for decisions, risks, and notes, then `roadmap_engineer_read_context` for selected entries that need full detail. Use the built-in `ask` tool to interview the user until the requested change, materiality, milestone substance, approval, and downstream planning impact are clear. When an amendment adds, removes, splits, merges, or reshapes milestones, ensure each resulting roadmap milestone still groups multiple meaningful deliverables or workstreams that belong together. All roadmap amendments require approval. Use `roadmap_engineer_amend` with `scope: roadmap`.
