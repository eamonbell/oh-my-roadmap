# /milestone:plan

Plan the next active roadmap milestone. Compare the selected approved roadmap milestone outline with decisions, risks, prior notes, amendments, closeout evidence, relevant existing code, and relevant documentation. Use `roadmap_engineer_search_context` first for decisions, risks, and prior notes, then `roadmap_engineer_read_context` for selected entries that need full detail. Expand that outline into a milestone plan; do not invent scope outside the approved roadmap. Do not pad the plan with filler tasks; every task must directly implement the approved roadmap milestone scope. Use the built-in `ask` tool to interview the user until no implementation decisions, acceptance gaps, ownership gaps, verification gaps, cleanup questions, test coverage decisions, or approval questions remain. Explicitly ask what test coverage the user wants based on the required implementation: which areas/tasks should create tests, which should only run existing tests, what detail those tests should cover, and what is intentionally untested or deferred. Define concrete executable tasks before dependency analysis or wave creation; every task needs objective, implementation notes, done criteria, task verification commands, dependencies, exclusive ownership, shared interfaces, and worker assignment. Assign each task to `worker-light`, `worker`, or `worker-heavy`: use `worker-light` for narrow low-risk localized edits, `worker` for normal bounded implementation, and `worker-heavy` for cross-module, API/schema, concurrency, migration, high-risk, or high-ambiguity work. Convert the test coverage decisions into task-level done criteria and verification commands. Perform dependency analysis over that task list, then group those task IDs into waves with goals, exit criteria, and review checkpoints. Include the persisted progress cursor initialized to the first wave with step `not_started`. Use `roadmap_engineer_transition` with `create_milestone_plan`, dispatch `wave-flow-checker`, record the result with `record_wave_flow_check`, revise with `update_milestone_plan` if it fails, and only validate/ask for approval after the checker passes.
